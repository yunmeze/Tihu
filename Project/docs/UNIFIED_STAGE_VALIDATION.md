# 统一开场阶段：验证范围

本记录区分数据校验、实际渲染与完整源工程导入。它不代表整图美术、完整游戏或 Windows 发行包验收。

## 本阶段已验证

1. **CPU / 最小发行闭包**：冻结 338 项原字节依赖，运行声明 207 项；源文件、注册、受控数据包与故障回退按精确身份校验。最小数据包已冷构建并完成空目录挂载检查。原 Python 构建源中的两项仅作为哈希依赖保留，不在游戏中执行。
2. **Linux 实际 source / PCK 画面**：22 项实际捕获记录中包含 10 个正向状态、四组南向画面贡献及故障恢复。源工程和数据包状态一致，恢复后像素差为零；三组 PNG 对逐字节一致。两边未经改写的默认入口均正常退出。此结果验证所测相机、状态与资格域，不能外推全地图或全部剧情。
3. **完整 Git 源目录冷编辑器门**：以冻结主仓完整 `Project` 加本阶段 53 项变化及唯一 `tools/.gdignore` 构成 4,053 个源文件。Linux Godot 4.6.3 冷编辑器导入 exit0，随后恢复原配置并启动默认入口，exit0；无脚本、解析或资源错误，全部 4,053 个原源文件 SHA 无漂移。隔离用户配置下的串行导入设置仅用于导入，原 `project.godot` 已还原。此门是 headless 导入与短启动，不冒充新增 GUI 交互或 Windows 测试。

此前实际自然主链已走通创建、五页开场、方丈与凌云子主线到 A00。手工稀有状态补测限定相机与姿态，尊重 STOP；不声称所有随机分支、早期支线均在本轮重新走完。

## 旧失败与修复边界

- 旧子类遗漏地面绑定曾使影/地表组合不一致；修复后以实际渲染对照核查，不能用单独两个模块的通过替代组合验证。
- 旧影合成矩形只覆盖部分 viewport；现在使用完整 viewport 合成，仍遵守原 receiver 资格域。
- 多次同显示帧刷新曾拖慢逻辑表现；当前保持 50Hz 权威逻辑并合并视觉刷新，排序与 owner 预筛也有独立差分验证。**50Hz 不是 50FPS**，软件渲染仍可能明显低帧率，不以滚动引擎读数宣称稳定 FPS。
- 验证工具曾有初始化、刷新时序或冷导入失败，修复测试入口后保留原失败事实。此前 SIGKILL 的根因没有被证实；降低导入并发或释放缓存后成功，不等于证明 OOM。
- 全目录静态审计发现六套历史导出插件模板包含只有安装后才成立的 `addons` 预载路径。新增的空 `tools/.gdignore` 隔离模板扫描；打包时仍由 Python 把模板复制到独立 `addons`。没有在模板子目录放 ignore，也没有删掉原字节依赖。完整源冷导入已验证这一组合。
