# Shared water candidate v4: binary/support recovery

This source-only candidate remains isolated by `.gdignore`. The current game does not load it. It has not been compiled or run in Godot. Keep the isolation until a bounded test/integration decision. No scene, autoload, registry or map is modified.

## Responsibility data

`data/core.png` and `data/support.png` are original-source-derived 192×192 L8 technical data. They are not artwork, water-depth labels, coastlines or passage boundaries. Both complete PNG hashes match the prior candidate, preserving exactly 9,402 core pixels and 32,256 owner-support pixels. The 22,854 supported noncore pixels all retain existing bank RGB. Outside support is not a bank label or a drawing authorization.

The prior protected/unresolved subdivision was not recovered. The new binary/support schema intentionally ships no state image and makes no tri-state restoration claim. Its prohibited set is exactly the prior supported noncore union because core and support are unchanged. Three original contexts share one candidate shape, with 27 original owner bindings, two world phases and all 21 cross-family holdouts retained.

`OWNER_CONTRACT.json` is the runtime binding for the original 27 owners and their three floor contexts, including rectangles, layers, order, flags and world phases. `MASK_CONTRACT.json` specifies the two responsibility channels and prohibited set. Neither document contains test outcomes or generated geometry.

## Preparation contract

With an explicitly supplied isolated module directory, the service accepts constant controls 0/1 and spatial modes `binary_negative_control` / `core_inset`. Callers provide the project root containing the paths in `INPUT_PINS.json`; the default module target is `res://scripts/art/shared_water_candidate_v4`. Every required input is hash-checked before its verified buffer is decoded. Missing/mismatched pins, schema, counts, subset, owner contract or readiness reject the request.

The D4 inset tests only supported noncore neighbors in a 3×3 D4-center neighborhood. It does not expand core and adds no smoothstep. Original rectangular owner drawing support and layer/order remain consumer obligations. Both color and independent weight caches belong to the same atomic generation.

Actual RenderingServer update completion, a required external validator, same-ticket deadline guards before/after validation and before publication, and delayed retirement protect preparation. The production clock is `Time.get_ticks_msec()` with the strict original `> 10000` millisecond boundary.

## Validation still required

Root must inspect actual same-camera A/B images after technical tests. Hard mask edges, pure-water padding, early generated-bank geometry and cross-family exits remain unaccepted. No default-game integration is approved by this package.
