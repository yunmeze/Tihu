## 2. 原单位→像素与父容器

每个数组控件名称后是固定字节18 01、uint16数组index、tag03、四个uint16几何值。全部原字节与字段保留，不依赖截图测量。

商品：
- X源值390+525×列，列0..7；Y源值405+525×行，行0..1。
- W=H=480。
- 除15得局部像素X=26+35×列，Y=27+35×行，W=H=32；与原GIF现成网格、32px物品图一一吻合。
- 购买按钮名后18 03及四几何值：3540,1575,1005,315 → (236,105,67,21)，尺寸与独立Buy.gif完全相等，位置与背景已绘购买按钮一致。
- PackageItem：X=180+525×列（0..5），Y=600+525×行（0..6），尺寸480² → 原背包局部(12+35c,40+35r,32,32)。

背景GIF后的属性序列也保留：tag04颜色4字节、tag05四uint16几何。ScriptBuy设计几何29280,3000,4935,2205；宽高除15正好329×147。PackageBox设计几何19080,600,3450,4785；宽高除15为230×319。

15单位/像素与VB Twips在96DPI下1440/96完全一致，因此可称“与Twips/96DPI一致并多点校验的原资源比例”。本次未读取运行时ScaleMode/系统DPI，不把它断言为任意DPI下固定15，也不采用Godot显示缩放倒推原单位。

父容器设计坐标ScriptBuy=(1952,200)、PackageBox=(1272,40)，显著可能是设计期停放位置，不能拿来当游戏窗口实时落点。子控件32px网格和按钮坐标相对父容器；绝对屏幕位置需原显示/重定位函数补证，当前不随意摆成Web竖屏布局。独立候选可只展示父容器局部原像素版式，并明确其展示位置是审阅承载位置。

## 3. 购买按钮事件链

原control record VA0x4046c0（40 bytes）：
- +0x18=0x407188事件表。
- +0x20=0x40c460，ASCII名称ScriptBuy_Buy。
- 事件表0x407188+0x28指0x40b06c；该thunk跳0x582950。
- 事件表0x407188+0x30指0x40b079；该thunk跳0x582c50。
- 0x582c50是已验证空槽→负重→金币→扣单价→GIVE一件的原购买handler，证据在apothecary-original-plan。

这证明原购买控件可触发已证交易，不能仅依据表槽号推定Click/MouseUp/左键/右键。成对handler像按压/释放视觉事件属于推测，尚未以VB事件IID/类型库验证。owned UI未来只可称“购买动作接同一单件语义”，不能宣传鼠标事件逐项原样。

## 4. 商品选择态、价格与信息框

ScriptBuy_Item元数据事件表VA0x407280：+0x28→thunk0x40b086→0x583000；+0x2c→0x40b093→0x5833b0。

已验证0x583000选择handler（shop-item-events.asm）：
- 按传入数组index读取商店数组0x63edc0，实例步长0x8c。
- 0x5830e2检查商品名称长度>1；空项转0x5832f5，selected全局0x63c76a设-1并隐藏选择控件路径。因此最后4格不能保留/借用旧商品选择。
- 非空项有多次读取商品格控件几何、写另一选择控件的同类属性；原资源另有ScriptBuy_Select记录和480×480尺寸，支持选择框随格位置移动。但选择框颜色/线宽的字段标签未完全核实，不能只按截图添加自创高亮。
- 0x5832a5读选中商品实例+0x84原price，转字符串并写经主对象+0x570取得的label。
- 0x5832ed将传入index写0x63c76a，后续购买handler读同一全局。
- 主对象+0x570与序列对应ScriptBuy_Money的定位还缺完整COM属性表解码；资源名与数字label说明用途相符，证据级别为“已证价格数值写label；具体control getter名待核”。

0x5833b0信息/悬停相关handler读取容器及商品格几何，最终0x583764调用主对象vtable+0x710并传数组index与位置，具备定位商品信息框的形状。EXE有公开名字updateBuyItemInf，但本次没有把其名字表与+0x710正式映射，不能宣布Tooltip字段/格式/触发延迟已复刻。保留原调用片段，不抄Web drawItemProperties当原tooltip。
