## 几何、owner、alpha 与遮挡契约

普通 Plant 的 world 左上为 `cell*(48,32)+(crop.x,32-original_height+crop.y)`，忽略资源 offset。owner key、完整 source_cell、flag、layer、sort_y、stable_source_order、atlas、native resource offset/bytes 与每帧 RGBA SHA 均已保存。每帧从现有 atlas 还原完整画布后对照 manifest RGBA SHA，不声称重解了未知原资源。

树292在 `(57,34)`，sort_y34；293–298在 `(55,37),(56,37),(58,37),(59,37),(60,37),(61,37)`，sort_y37；全部 layer1，稳定序仍 x-major。根 owner flag=-1，其他6个 flag=0。灌木143在 `(57,35)`，sort_y35、flag0；144–146在 `(56,38),(57,38),(58,38)`，sort_y38、flag=-1。全部保留原值。两组都是同时存在的空间切片，绝不是动画帧。

每组文件：
- `_source_native.png`：未放大原RGBA合成，只用于几何/木质结构读点；旧黄色树与旧像素材质绝不是Earth风格参考。
- `_alpha.png`：原透明度，无人为抹色；包含旧烘焙棋盘影。
- `_owner_ids.png`：单通道0透明，1..N为清单顺序，保留原alpha覆盖位置与归属；这是原像素归属证据，不是新树可直接套用的物理材质遮罩。
- `_geometry_only.png`：原alpha配中性颜色，供生图时抑制旧美术颜色影响；仍含棋盘影，只能理解为旧占位范围，不能逼模型把所有这些像素重画成树叶。

原透明空洞和层次必须可复核；禁止把整组 bbox 填实或把树压成单个根sort sprite。树在角色 y34–37、灌木在 y35–38之间有分层差异，前后关系不能被全局贴图吞掉。碰撞与alpha不是同一回事：根/灌木 blocked格不移，其他原可走格保持可走，不增花池/岩石/护栏来制造假障碍。

原树298是旧影外缘；其余叶/树干与旧影存在混合。灌木深色同样出现在叶内，禁止按RGB全局删除黑色。源alpha不能不加区分地裁成新实体，也不能保留旧棋盘影再叠新影。未来新组需明确每个owner的实体归属或显式空项，整组原子成功/失败。若新轮廓在原alpha外扩张，必须先做源轮廓/通路及归属审查；本阶段没有批准扩大遮挡。

## Concept 输入及材质规则

唯一新风格依据是 `earth_base_style_concept_v1/concept.png` 和 `EARTH_ART_BIBLE_V1.md`。`concept_crops.json` 精确记录原尺寸、裁框、SHA。局部PNG直接原分辨率裁切，没有放大：
- `concept_tree_branch_foliage.png`：绿色阔叶层次、树枝/树干结构、受光组织。
- `concept_bark_detail.png`：灰棕树皮与分叉连接，不作为根点或尺度标定。
- `concept_shrub_material.png`：小叶簇密度、自然不齐轮廓、偏暖亮部/偏冷暗部。

局部内的草地、建筑、石质花池仅为上下文，禁止搬入新PNG。现实绿色阔叶树与灌木，不能保留旧金秋黄树、发光异星植物或庭院外观。概念高光偏黄只用于受光叶尖；主体应读为绿。统一左上/后侧日光、预期右下落影，精确投影向量尚未标定，不复用旧庭院方向。

## 下一轮生图输入包（待批准，不执行）

首轮严格两张独立完整主体：树一张、灌木一张；共享上述concept参考，分别使用对应源native、geometry_only及本契约。不要以整屏截图作“背景重画”输入。源native只约束几何、完整空间切片结构和根/支撑位置，concept只给新材质/光照，不导入新地形。树冠不要求保留旧叶形纹理，但不能漂移外包络/根与通路关系。

建议树以4 texels/逻辑单位工作：有效组区域1248×1244，根约组内(476,1200)，误差仍按逻辑±4读；最小真实2×为624×622。灌木推荐496×420，最小248×210。若服务返回其他画布，先量有效主体与源逻辑轮廓，采用统一缩放/平移注册；透明padding不能冒充密度，不可分别拉宽/拉高或逐切片形变。所有主体从生成raw直接下采样至密度2或4，不能先做312×311/124×105再放大。原PNG仅1×证据，绝非高清成品。

树提示核心：纯2D源斜俯视游戏角度，完整现实绿色阔叶树，灰棕分叉树干和可读根部；保留源312×311的完整占位关系、基脚位置、原大轮廓尺度；以concept绿色叶片、细分枝条、自然层次重画，不继承旧黄树色彩或像素风。透明背景，无地板、花池、人物、建筑、白底、棋盘影或独立地面落影。保留树体自阴影与紧贴根部的材质暗部，跨地面投影另做。光照按concept左上暖日光、冷环境填光；不加透视消失点或景深。

灌木提示核心：同样纯2D斜俯视、现实绿色小叶灌木，低而圆且自然不齐，原124×105尺度和下缘支撑带；绿叶簇有疏密和枝叶结构，避免球形塑料、均匀噪点或极黄叶尖。透明背景，不加花盆、花池、石块、木桩、地板或投影。只画完整灌木主体，不能把四owner画成四棵灌木或四相动画。

叶片/枝条材质可以独立新生细节，不能将放大旧像素叫高清。精确切片注册、alpha归属以及环境影属于下一阶段技术处理和验收，生成结果不直接进入运行路径。

## 验收边界

1. 输入hash、35 owner清单、当前地图flags保持原值；首轮只接7+4 owner。保持每owner稳定排序，任何缺资源/尺寸/hash错误整组回退，不能半树旧半树新。
2. 先检查完整树和灌木raw100%，再看统一变换叠原轮廓、根/支撑带；树根人工证据±4，不假称精确测量。新灌木基脚仍须独立读点，不把bbox底当根。
3. PNG、后续atlas、Godot导入、绘制矩形、真实2×截图五处验证密度。最终视野1536×1024呈现同一768×512 world，不能低分Viewport先合成后放大。
4. 当前固定样区同相位源/新对照；实际原路线绕树根、灌木前后以及切片sort_y交界测试。原flag=-1格仍不可走，可走格不能画成高障碍。保持原A*、走位、主角尺度/脚底，不移动主角来救图。这里仅提出测试，未声称执行。
5. alpha缝、叶洞、支撑带和前后遮挡在静止及移动时无抖动/吞人。单张素材和离线图不能替代实机核验。
6. 首轮无新落影时明确影缺失；保留源资源时不再叠影。若制作新环境影，单独记录右下向量、接收平面与原影剔除证据；未经验证不覆盖人物/平台。不得以整屏遮罩掩盖owner错误。
7. 不因这两组通过而宣布全图植被高清，不自动扩树种库或推广其他位置。
